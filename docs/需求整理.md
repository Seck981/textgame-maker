## 二、五个功能的最终形态

### 功能一 · 页面排版（**界面完全由使用者写，引擎不构造任何 DOM**）

三个编辑器，每个 = **HTML 输入框 + CSS 输入框 + JS 输入框 + 实时预览 + 可交互试用**

| 层 | 默认内容 |
|---|---|
| char 楼层 | 现在这套手机界面 |
| user 楼层 | 现在这条黑色横条 |
| 悬浮楼层 | 现在这个"楼层附加内容"面板 |

**架构**（这是关键，不是"填空模板"）：

```
酒馆楼层
 └─ <iframe sandbox="allow-scripts">     ← 使用者的 HTML/CSS/JS 全在这里跑
      引擎 postMessage ──→ { lines, bg, cast, assets, size }
      使用者代码 ──postMessage──→ { type:'advance' | 'setBg' | 'bubble' | 'setSize' }
```

- 引擎**只做四件事**：解析脚本 / 准备素材 / 传数据 / 接动作
- **多页面、多视图完全由使用者的 JS 自己管** —— 例如加一个"返回"按钮跳到手机 APP 页面、做二级页、做设置页，都是他自己的 DOM
- **尺寸由使用者的 CSS 决定**；另外提供 `ctx.setSize(w, h)` 让代码动态改
- 素材：引擎把图片转成 **blob URL** 一次性注入，直接 `<img src>` 就能用
- 预览用同一个沙箱，报错捕获后显示在预览下方
- 每个编辑器都有「恢复默认」按钮

**引擎给使用者 JS 的 API**

```js
ctx.lines / ctx.bg / ctx.cast / ctx.assets / ctx.data
ctx.setBg(key) / ctx.say(i) / ctx.next() / ctx.prev()
ctx.fx(name) / ctx.bubble(name) / ctx.setSize(w, h)
ctx.on('advance' | 'click' | 'swipe', fn)
ctx.log(...)                    // 打到预览区下方的控制台
```

### 功能二 · 导入图片
- **背景**：导入（本地文件 / 图床 URL）→ 在手机预览上拖动缩放取景 → 记录 `{src, scale, offsetX, offsetY}`
- **立绘**：创建**角色组** → 组内创建**情绪立绘**（提示用情绪命名，如 `开心`/`委屈`）→ 每张可调初始定位
- **角色组设一个默认锚点，组内所有立绘继承**，单张可覆盖
- 存储：`IndexedDB`（图大；且**不跟卡走**、不公开）

### 功能三 · 特殊演出制作（两组分开）

**A. 立绘/画面演出**
- 内置列出 8 种：`in / shake / jump / zoom / dim / bright / flash / bubble`
- 可新建演出组，后面放代码（CSS keyframes 或 `(el, ctx) => {}`）—— **纯动画，无任何网络限制**

**B. 情绪气泡（贴纸）**
- 内置 20 张贴纸（上面那批）
- 可导入自己的贴纸并调初始位置
- 每个气泡**单独配置入场动画**：上下 / 左右 / 斜向 / 闪烁两下 / 自定义代码
- 触发：AI 在台词第 4 字段写 `bubble:love` 这种

### 功能四 · 提示词（两块，用途完全不同）

**4A · 剧情提示词** —— 发给"正在跟你聊天的那只 AI"
- 汇总当前素材库：有哪些背景 / 有哪些角色和表情 / 有哪些演出 / 有哪些气泡
- 显示要发给 AI 的整段提示词，**可编辑**
- 由脚本在生成前注入（`setExtensionPrompt`），**不再写在角色卡 description 里**

**4B · 开发提示词** —— 发给"帮你写代码的那只 AI"★ 这是你要的那份
- 没有它，别人打开编辑器也不知道怎么写 → **必须有，而且要是现成可复制的**
- 内容由插件**根据当前素材库动态生成**，包括：
  1. **运行环境**：沙箱 iframe（`allow-scripts`，无 `allow-same-origin`）、不能碰酒馆 DOM、**不能发网络请求**、**不能用 CDN**（要断网可用）、只有原生 HTML/CSS/JS
  2. **引擎会给什么**：`postMessage` 的完整数据结构（`lines / bg / cast / assets / size`）+ 每个字段的样例
  3. **`ctx` API 全表**：`setBg / say / next / prev / fx / bubble / setSize / on / log` 的参数和例子
  4. **素材清单**：内置 20 个气泡名 + 使用者导入的立绘组和表情名 + 背景名（带实际 `blob:` 或名字）
  5. **画面约束**：宿主宽度约 400px、高度自适应、素材都是透明底、移动端触摸优先
  6. **输出格式**：要求 AI **只输出三段**，用 ```html / ```css / ```js 围栏，方便直接粘回插件
- 插件里配一个 **「复制开发提示词」按钮**，一键全选进剪贴板

**代码替换的回路**（你说的"都通过放到插件里面的代码替换来完成"）

```
插件里点「复制开发提示词」
   ↓ 粘到任意 AI 对话里，再加上 "我要一个能返回的 APP 页面"
AI 输出三段代码
   ↓ 直接粘贴回插件的 HTML / CSS / JS 三个输入框（或整段粘贴，插件自动拆围栏）
预览区立刻出效果 → 不满意就再让 AI 改
   ↓
导出 zip（代码 + 素材）→ 别人导入素材包就能用同一套
```

配套要有：
- 三个输入框用**等宽字体 + 行号**，支持整段粘贴自动拆分围栏
- 每个框都有 **「恢复默认」**
- 一段代码可以**单独导出/导入**（.txt / .html），方便备份和分享

### 功能五 · 导出
导出 zip：

```
文字游戏页面制作器.zip
├── 文字游戏页面制作器.js    ← 酒馆助手脚本（三层模板 + 演出代码 + 提示词）
├── manifest.json            ← 背景/角色/气泡 映射表 + 变换参数
└── assets/                  ← 本地素材原图（不压缩）
    ├── sticker/*.png
    ├── bg/*                  ← 使用者自己导的
    └── chara/<角色>/*        ← 使用者自己导的
```

对方：**悬浮窗「导入素材包」→ 选 zip → 解压进 IndexedDB → 直接可用**。
另外保留**纯 URL 模式**（只用图床链接，导出不带图）。

**内置 vs 导入**：内置的 20 张贴纸默认跟随导出包一起走；
所有素材（内置的、自己导的）**都能单独删除**。

## 三、一个必须你拍板的技术取舍（新发现）

20 张贴纸 **7.64 MB**。你要求"烘焙进本体、断网也能用、跟着导出的脚本一起走"。这有两条路：

| 方案 | 断网可用 | 跟脚本走 | 体积 | 问题 |
|---|---|---|---|---|
| **① 放扩展目录里的 PNG**（推荐） | ✅ | ✅（打进 zip） | 7.64 MB | 对方需要导入素材包才有贴纸 |
| **② base64 内联进 .js** | ✅ | ✅（自带） | **约 10.2 MB 源码** | 酒馆助手脚本和角色卡 PNG 会大到加载困难 |

②的体积算法：PNG 7.64MB → base64 ×1.33 ≈ **10.2MB 的纯文本**塞进一个 .js 里。
这个脚本还要再 base64 进角色卡 PNG → 卡片会变成 14MB+，酒馆读取会非常慢。

**我的建议**：走 ①，但把"内置贴纸"定义为**扩展自带资源**（不是使用者导入的），
导出 zip 时自动带上，对方导入后就完全本地化、断网可用。

如果你坚持要"单个 .js 自带全部贴纸"，那就只能对这 20 张**单独**做 WebP q=92
（视觉几乎无损，7.64MB → 约 1MB，base64 后约 1.4MB，可接受）。
**注意：这只影响内置贴纸，你自己导入的背景/立绘仍然原图不压。**

# 十一、v6 补充：站位改成可拖动配置

**需求**：站位不该只有 left/middle/right 三个固定位置。
- 在「页面中能占多少个角色」这块里，**可以点一下，把导入的角色立绘素材拖过来用**
- 然后把素材**在页面预览上拖动**，决定每个站位实际出现在哪个位置
- 逻辑和「导入立绘时决定立绘出现在哪」是同一套

**已定下的数据结构**（先埋好，P2 做界面）

```js
project.slots = [
  { key: 'left',   x: 22, y: 100, scale: 1.0 },   // x/y 是相对舞台的百分比, y=100 表示贴底
  { key: 'middle', x: 50, y: 100, scale: 1.0 },
  { key: 'right',  x: 78, y: 100, scale: 1.0 },
]
```

- 预设三套（单/双/三角色）只是**预填一组坐标**，拖完就按拖的来
- 自定义关键词可以加任意多个，每个都能拖
- 导出时把坐标写进脚本，引擎按 `x/y/scale` 摆立绘（现在是写死的 18%/50%/82%）

**本期已实现的过渡方案**：引擎先支持 `left/middle/right` 三个类 + 任意自定义关键词的
`--gv-slot-x` 百分比；等 P2 的拖动界面做好，再换成完整坐标。

# 十八、本轮修复 + 新需求

## 修好的 bug（你报的两个）

根因是同一个：我用了 `object-fit: cover` + `object-position`。
- `cover` 让图片永远填满框 -> **只能往里缩，缩不小**
- 9:19.5 的竖框里放竖图，纵横比接近 -> `object-position` 纵向**几乎没有余量**，所以只能左右移

改成纯 transform 模型：`transform: translate(x%, y%) scale(s)`

实测：
```
拖动     translate(69.05%, 63.19%) scale(1)   ← 上下左右都能动
滑块范围 min 0.3 / max 3
缩小到   scale(0.55)                          ← 能缩小了
放大到   scale(1.8)
```
引擎的 `.gv-bg`（背景）也一起改成了 transform 模型，所以背景同样能缩小 + 上下移动。

## 新需求（待做）

**页面排版 -> 素材定位的框大小要能传参**

用户原话要点：
- 点「定位」后弹出的那个调整框，它的大小应该由 **char 页面排版里的 CSS** 决定
- 具体做法（用户的想法）：
  1. 程序自己去 char 模板的 CSS 里找**相关命名**的尺寸数据
  2. **读出来显示在旁边**
  3. 这个显示的数据**可以改**（防止自动读错）
  4. 改后的值决定定位框的大小
- 背景同理

落地设计（记下来）：
1. 在 char 模板 CSS 里找第一个匹配 `.phone` / `.stage` / `.box` 的规则，解析 `aspect-ratio`、`max-width`、`width`
2. 在「页面排版」页每层下方显示一行「定位框尺寸：宽 [___] 高比 [___]」，可改
3. 存进 `project.frameSize = { w, aspect }`
4. `frameEditor` 用这个尺寸渲染框
5. 导出时一起带进 manifest

## C. manifest.json 是什么（口径统一）

素材包 zip 里的**说明书 + 参数表**（不含图片本身）：

- 名字 → 文件路径（如 `房间` → `assets/bg/房间.png`）
- 每张图的变换参数：背景/立绘的取景 `fit`（位置 + 缩放）、立绘锚点、气泡默认落点与单张贴纸落点、每张贴纸的入场动画、自定义气泡动画 CSS、站位关键词与站位坐标、自定义演出代码、音频外链
- 卡/引擎启动时读它，把「AI 写的关键词」映射到真正的图片地址上（`setAssets` / `setBubbles` / `setEffects` / `setSlots`）

★ **素材包 zip = `assets/` 图片 + `manifest.json` 说明书，两样必须一起给**：
只给图片，引擎不知道哪张图对应哪个名字/哪张立绘/哪个气泡；只给 manifest，没有图可读。

2. 烘焙时（`bake-tpl.mjs`）**同一份源码产出两个默认模板**：`DEFAULT_TPL.char`（有音频）和 `DEFAULT_TPL.charNoAudio`（把标记块剥掉）
3. 竖版 / 横版两套模板都按这个机制走（横版做的时候一起带上）

### F.1 页面排版的按钮

用户原话：截图那两个按钮「恢复默认」和「清空（用引擎自带长相）」看起来功能一模一样，不明白为什么要分两个。

- **保留「恢复默认」**
- **原来「清空」的位置 → 换成「从本地导入素材」**
- ✅ **已确认（用户实测 + 代码核对）：这两个按钮在预览里确实看不出区别，删掉「清空」**
  - 代码事实：`恢复默认` → `pages[层] = {html,css,js}`（插件内置模板）；`清空` → `pages[层] = null`
  - 但编辑器/预览在 `pages[层]` 为空时会**退回默认模板**（`curT = cur.pages[tplTab] || DEFAULT_TPL[tplTab]`），所以点完两个按钮**屏幕上都是同一份默认代码、同一个预览** —— 用户没看错
  - 「引擎自带长相」只在**导出之后**才体现：null 那一层在卡里走引擎自带界面；带模板则用模板
  - 决定：**删掉「清空」**，位置给「从本地导入素材」；导出的三层永远带模板

### F.2 从本地导入素材（页面排版用）

用户想法：
- 点「从本地导入素材」→ 弹窗，里面能**导入本地图片**
- 弹窗里能看见**一共导入了多少素材**
- **不需要重命名**功能
- **可以删除**
- 按钮旁边给一句提示：**代码里用了本地素材的话，要再从这里导入一遍**

我的评估（**这条需求是对的，而且是必须的**，有实测依据）：
- 页面排版的模板跑在 `sandbox="allow-scripts"` 的 iframe 里（独立源）。**实测**：CSS/HTML/JS 里写 http、根相对、相对路径、`file://` 的图**一律加载不出来**（父页面同样的地址 OK、iframe 里 ERR），只有 `data:` 能显示；父页面造的 `blob:` 传进去也是 ERR。
- 所以「代码里引用本地图片」这条路本来就走不通，**必须由插件把图片转成 data URL 交给模板** —— 用户这个"再导入一遍"的设计正好绕开了这个坑。

需要一起定/一起做的（我建议的落地方式）：
1. **模板怎么拿到这些图**（三选一，我推荐 ①+③ 组合）：
   - ① 挂到 `ctx` 上：`ctx.files = { '文件名': 'data:image/png;base64,…' }`，模板 JS 里 `img.src = ctx.files['bg.png']`（预览和导出都注入，同一套）
   - ② 插件把它们写成 CSS 变量注入（如 `--tgm-f'bg.png'` → 实际用 `--tgm-file-1: url(data:…)`），CSS 里写 `background-image: var(--tgm-file-1)`
   - ③ 给每个文件一个「复制成 CSS 片段」按钮，直接生成 `url(data:…)` 让人粘进 CSS（最简单，但 CSS 会变得很长、换图要重粘）
2. **重名**：不重命名的话，文件名就是 key → 重名自动加 `-2` 后缀并显示出来
3. **删除**：删掉后如果模板还在引用它，预览里那块就空着 —— 弹窗里给个"被引用中"的标记更稳
4. **和素材库的关系**：如果同一张图已经作为背景/立绘/贴纸导入过，能不能直接挑（免得导两遍）→ 建议弹窗里加一个「从已有素材里选」
5. **导出必须带上**：这些本地素材要进素材包 zip（如 `assets/page/<文件名>`）+ manifest；按第 4 条纯 URL 模式，链接类的直接写进脚本映射表
6. **提示文案**：按钮旁边写一句「代码里引用了本地图片的话，要在这里再导入一遍（外面的路径在预览里加载不出来）」

### F.4 UI 素材的定位（用户口径，别搞混两套提示词）

- 「从本地导入素材」导进来的是 **UI 素材**：给**页面排版那三层代码**用的图（写死在 UI 里，由写 UI 的 AI 按用户给的文件名去引用）
- 它 **不进 4A 剧情提示词**（聊天 AI 不需要知道，也不该让它自由决定 UI 长什么样）
- 但**导出时必须进资产包**（`assets/page/<文件名>` + manifest），否则别人拿到脚本 + 素材包，页面排版里的图是空的
- `ctx.files` / CSS 变量里带的就是这些图（名字 = 文件名）
